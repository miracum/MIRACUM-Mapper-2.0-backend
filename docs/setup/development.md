# Development

The following sections will provide information on how to develop the project locally, how to run tests, how to run and debug the app locally.


## Prerequisites

A Dev Container is provided to run the project in a containerized environment and make development easy as it has all prerequisites installed. To use it, you need to have Docker installed on your machine. The Dev Container Extension for VSCode is also recommended. Please refer to the [Dev Container Documentation](https://code.visualstudio.com/docs/remote/containers) for more information.


## Running the application

The easiest way is to create all services (except the actual backend) in a dockerized environment using the `docker-compose-dev.yaml` file:
```bash
docker compose -f docker-compose-dev.yaml up -d
```
Afterwards, the backend can be run and debugged by using the `./vscode/launch.json` file. Just click on `Run and Debug` and select `Launch Miracum Mapper Docker`.

When the applications starts, it waits until the database and keycloak are reachable.

At this point, the backend api should be available which can be tested by accessing `http://localhost:8080/ping`.

Keycloak can be reached at `http://localhost:8081`. Please refer to the [Keycloak Setup Guide](./keycloak.md) for setting up the miracum-mapper client.


## Tools and tips for development

A good entry point into development is to get an overview of the code structure. More information on the code structure can be found in the [Code Structure Documentation](/docs/implementation/code.md).

### Database
The structure of the database is described in the [Database Documentation](/docs/implementation/database.md).

During development, it could be useful to directly inspect or modify the currently stored data. The easiest way is to use the [PostgresSQL](https://marketplace.visualstudio.com/items?itemName=cweijan.vscode-postgresql-client2) VSCode Extension which is preinstalled when using the DevContainer setup for development. Using the extension, you can create a new connection to the database using `host.docker.internal` as `Host`, `5432` as `Port`, `miracum_user` as `Username`, `miracum_password` as `Password` and `miracum_db` as `Database`.

### API
Boilerplate Code for the go server gets generated by [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen). Every time the API specification is changed, the code generator has to be executed. For more information see the [API Documentaion](/docs/implementation/api.md).

For testing the API Endpoints many tools are suitable but a very simple way to do it is using the [Swagger Viewer](https://marketplace.visualstudio.com/items?itemName=Arjun.swagger-viewer) VSCode Extension which is preinstalled when using the DevContainer setup for development.

In order to test the API using the Swagger Viewer, the `servers` section with the development server in the [openapi.yaml](/api/openapi.yaml) has to be commented in.

When hosting the frontend, you should be able to login to the frontend and then copy the access token for the api in the `Profile` section. A guide on how to host the frontend can be seen in the [Frontend Readme](https://github.com/miracum/MIRACUM-Mapper-2.0-frontend). By default access tokens are only valid for one minute and get refreshed automatically by the frontend. This can be frustrating when developing as this means you have to copy a fresh access token every minute. To extend the duration of an access token, login to keycloak, click on `Realm Settings` > `Tokens`, scroll down to `Access Tokens` and adjust the `Access Token Lifespan` accordingly.

### Other tools
For visualizing the database structure the tool [DrawSQL](https://drawsql.app) was used.


## Running the application locally

The application can also be run locally.

### Prerequisites
`Go 1.24` is used to develop the project so it has to be installed. `Make` has to be available to use the Makefiles for building the Application. Docker is necessary anyway to run keycloak in an containerized environment and start the postgres database.

### Running the application

The application can be run locally using the following command:

```bash
go run cmd/miracummapper/main.go
```

There is also a `Makefile` defined to create the binary for a linux environment using the following command (This makefile is also used in the build stage of the docker container to build the binary):

```bash
make
```


## CI/CD Pipeline (GitHub Actions)

The project uses GitHub Actions as a CI/CD pipeline. The workflow is defined in the `.github/workflows` directory. Actions from the Miracum Project [.github](https://github.com/miracum/.github) repository are integrated to the workflow. The pipeline is divided into the jobs:

- `Static Code Analysis` is performed in the lint job using the Miracum Project `standard-lint.yaml` workflow. Additionally a `check-oapi-codegen` job is defined which checks if the generated code from the OpenAPI specification file is up-to-date with the spec file.

- `unit-test` are performed afterwards to test the individual functions of the application.

- TODO: `integration-test` will be added to test the application as a whole.

- In the `build` job the docker image is build, scanned and pushed to the GitHub Container Registry.
